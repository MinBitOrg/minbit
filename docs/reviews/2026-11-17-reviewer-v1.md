## Findings that apply to every PR

1. **Same identity for author and reviewer.** The ruleset requires 0 approvals, so the agent
   review is advisory. Blocking now relies on unresolved threads or draft status.
2. **Ledger entries live on branches.** Each PR appends to `state/ledger/2026-11.jsonl`, so every
   pair of open PRs conflicts there, and `minbit digest` on `main` cannot see runs whose PR is
   still open (validated: on #22's head, "Done" lists only the two entries on that branch).
3. **No `in_review` → `done` step.** MB-004 is still `in_review` on `main` although #14 merged on
   16 Nov; the digest then lists it under "Waiting for you" (validated on #22's head).
4. **Stacks.** #21 and #22 are built on #20. Merging either one first also merges #20.

## Prompt improvement proposals (for the planner / maintainer)

1. **Separate reviewer identity** (GitHub App or bot account) so the reviewer can submit real
   `APPROVE`/`REQUEST_CHANGES` and the ruleset can require 1 approval. Needs `needs-human:security`.
2. **Ledger outside PR branches** — e.g. one file per run (`state/ledger/2026-11/<ts>-<task>.json`)
   so appends never conflict, or the heartbeat writes the ledger to the digest issue until merge.
   Changes a persisted format → `needs-human:schema`.
3. **Heartbeat reconcile step** in `genesis/heartbeat-prompt.md` step 2: for each `in_review` task
   whose PR is merged, `minbit set-status <id> done` on the next branch (closed-unmerged →
   `queued`). Already logged as a follow-up on #21.
4. **Heartbeat: state the effective queue.** `minbit next` on `main` returns tasks that already
   have open PRs (today it returns MB-001, PR #16). Add: "compute `next` on the newest open
   planner branch, or skip tasks whose id appears in an open `agent/*` PR".
5. **PR template: add a `Base:` line** ("main" or "stacked on #NN") so stacks are visible on a phone.
